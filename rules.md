## Token-saving tools (claude-tuning)

- Online search and reading web pages: use the deepseek-search tools (`search`, `fetch`) instead of WebSearch/WebFetch. Search first, pass `more_queries` for broad research, and read only the 1–3 results that matter with `fetch`. When a call fails, its error says the built-in tool is unlocked; use that one then.
- Shell commands are compressed by rtk's hook (git, tests, builds, listings…). When you need a command's raw, unfiltered output, run it as `rtk bypass <command>`. Run commands unpiped so rtk, not `head`, decides what to drop.
- Large outputs, logs, files you need only parts of: use the stash tools (`stash_run`, `stash_index`, then `stash_search` / `stash_get`) instead of reading raw bytes into context.
- quicksilver first whenever you would otherwise read a lot just to decide what matters: which files deal with a concept ("which files handle auth", "where do we issue refunds"), the real failures in a long log, labels for many items, the right lines in a huge file. Run `qs filter|rank|find|classify|ask` (or `node <quicksilver skill dir>/scripts/qs.mjs …` when `qs` is not on PATH), read only what it returns, and check its `?` items yourself. How it splits with the others: codebase-memory for named symbols (where is `fooBar` defined, who calls it); stash for reading parts of one big output you already have; grep for exact strings. Skip quicksilver when the input is a few files you can just read.
- Ponytail rules are injected each turn; follow them unless told "stop ponytail".
- If codebase-memory is installed: for code structure questions about named symbols (where is X defined, what calls X), use `search_graph` / `trace_path` / `get_code_snippet` before Grep or Read, and index the repo first (`list_projects`, then `index_repository`). Confirm "who calls X" counts with `search_code`; the graph misses calls through indirect types.
